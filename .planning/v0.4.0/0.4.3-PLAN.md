# Phase 0.4.3 Plan: Resume 与 Export 闭环

**Version:** v0.4.0  
**Phase:** 0.4.3  
**Status:** Planned, not implemented  
**Depends on:** 0.4.1 安全与设置骨架, 0.4.2 扫描与搜索闭环  
**Primary files likely touched during implementation:** resume service, export service, redaction engine, API handlers, SessionDetail UI  
**Non-goal for this planning step:** Do not implement code while writing this plan.

## 1. Goal

把会话详情从“可查看”推进到“可继续”和“可沉淀”：用户可以在 Web 中检查恢复条件、复制恢复命令、导出完整会话，并选择安全脱敏导出。

## 2. User Stories

1. **作为中断任务的开发者**，我希望查看会话时直接知道它能否恢复，并复制正确命令。
2. **作为需要复盘的开发者**，我希望导出完整 Markdown，而不是只有摘要 preview。
3. **作为需要分享会话的用户**，我希望安全导出能识别并替换常见敏感信息。

## 3. Scope

### In scope

- Resume service。
- `GET /api/sessions/:id/resume-check`。
- ResumeCard UI。
- Raw transcript reader service。
- Export service shared by CLI and Web。
- Markdown export with full available event content.
- JSONL export behavior clarification.
- Manifest generation。
- Export directory `.gitignore` creation。
- Redaction engine with 12 base rules。
- Redaction preview API。
- ExportCard and RedactionPreview UI。

### Out of scope

- AI-generated summaries。
- Skill Forge generation。
- Custom redaction rules UI。
- Export editor。
- Cloud/share links。

## 4. Locked Decisions

1. Export cannot rely only on `TranscriptEvent.preview`.
2. CLI and Web export must use the same service.
3. Safe export must actually apply redaction.
4. Redaction preview must not reveal full secret values.
5. Resume command is copy-first, not auto-execute.

## 5. Resume Design

### 5.1 API

```text
GET /api/sessions/:id/resume-check
```

### 5.2 Response

```ts
interface ResumeCheck {
  ready: boolean
  command: string | null
  shell: 'bash' | 'zsh' | 'powershell' | 'cmd' | 'unknown'
  checks: ResumeCheckItem[]
  warnings: string[]
}

interface ResumeCheckItem {
  key: 'project_path' | 'transcript_file' | 'claude_cli' | 'shell'
  label: string
  status: 'pass' | 'warn' | 'fail'
  message: string
}
```

### 5.3 Checks

- Project path exists.
- Transcript file exists.
- Claude CLI available in PATH.
- Shell type known or fallback command available.
- Branch is known, as warning only.

### 5.4 UI

`ResumeCard` in report/detail panel.

States:

- ready: “可以继续” + copy command button.
- warn: “可以尝试继续” + warnings.
- fail: “暂不可恢复” + failed checks.
- loading: skeleton/checking state.
- error: retry state.

## 6. Export Design

### 6.1 API

```text
POST /api/sessions/:id/redaction-preview
POST /api/sessions/:id/export
```

### 6.2 Request

```ts
interface ExportRequest {
  format: 'markdown' | 'jsonl'
  safe: boolean
  include_manifest: boolean
}
```

### 6.3 Result

```ts
interface ExportResult {
  output_path: string
  manifest_path: string | null
  redaction_enabled: boolean
  redaction_count: number
  source_hash: string
}
```

### 6.4 Raw transcript reader

Needed because current storage has preview only.

Behavior:

- Use session file path.
- Use event `fileOffset` and `byteLength` when available.
- If offset invalid, fall back to streaming line scan by sequence/session metadata.
- If source file missing, export degraded metadata + stored previews with warning.
- Preserve UTF-8 safety.

### 6.5 Markdown content

Include:

- Session title and metadata.
- Source and export metadata.
- Timeline grouped by event type and sequence.
- User/assistant content when recoverable.
- Tool call summaries.
- Error markers.
- Manifest reference.
- Lightweight watermark.

### 6.6 JSONL behavior

For v0.4.3 choose one:

- Copy source JSONL into export directory, with optional safe redaction applied line by line.
- Or explicitly label JSONL export as “source file copy command” and keep real copying for later.

Recommended: copy source JSONL for raw export; for safe export, write redacted JSONL.

## 7. Redaction Design

### 7.1 Base rules

1. API key
2. Anthropic/OpenAI style key
3. GitHub token
4. AWS key
5. JWT
6. Authorization header
7. SSH private key
8. Database connection string
9. `.env` sensitive key-value
10. Home path
11. Email
12. Private IP

### 7.2 Replacement format

```text
[REDACTED:github_token]
[REDACTED:home_path]
[REDACTED:email]
```

### 7.3 Preview

Preview returns counts and short context with masked value, not raw secret.

```ts
interface RedactionPreview {
  total_matches: number
  items: RedactionPreviewItem[]
}

interface RedactionPreviewItem {
  rule: string
  count: number
  sample: string
}
```

### 7.4 False positives

v0.4.3 principle: when unsure, redact. Test/fake/dummy/example can produce warning but should not weaken safety by default.

## 8. Frontend Design

### 8.1 ExportCard

Place below ResumeCard in report/detail panel.

Controls:

- Format: Markdown / JSONL
- Mode: Safe export / Raw export
- Redaction preview button for safe mode
- Export button
- Result path with copy button

### 8.2 RedactionPreview

- Show rule names and counts.
- No full secret display.
- Confirm button: “导出脱敏副本”。
- Raw export requires warning confirmation.

## 10. Acceptance Criteria

- Web detail shows resume readiness.
- Copy resume command succeeds with feedback and never auto-executes.
- Web can export Markdown.
- CLI and Web export produce consistent outputs through shared service.
- Safe export replaces known sensitive sample values.
- Manifest file is generated.
- Export directory contains `.gitignore`.
- Source file missing yields clear degraded export warning, not crash.

## 12. Risks

| Risk | Mitigation |
|---|---|
| Raw transcript offsets stale | Fallback to streaming scan and mark warning |
| Redaction misses uncommon secret | Document rule-based limitation, prefer over-redaction |
| Large export blocks server | Stream where practical or run background job in future |
| Clipboard failure silent | Always show error fallback with selectable command/path |

## 13. Definition of Done

This phase is done when a user can safely continue or export a selected session from the Web UI, with CLI and Web sharing the same resume/export business logic.
