## 4. Quality Gates

v0.4.0 不得发布，除非以下检查通过：

```bash
cargo test
cargo clippy -- -D warnings
cd frontend && npm run build
```

Recommended additional checks:

```bash
cd frontend && npm run lint
ccmemo demo
ccmemo serve
```

If lint currently has known baseline issues, document them explicitly rather than hiding failures.

## 5. UX Quality Pass

### 5.1 Required states

For each core operation, verify these states exist:

| Operation | Empty | Loading | Success | Error | Disabled |
|---|---|---|---|---|---|
| Scan | yes | yes | yes | yes | while running |
| Search | no data + no match | debouncing/searching | results | API error | n/a |
| Resume | no session | checking | ready/warn | failed/error | no session |
| Export | no session | exporting | exported | failed | invalid form |
| Settings | n/a | loading | loaded | failed | readonly fields |

### 5.2 Copywriting checks

- No vague “安全无忧” claims.
- Safe export described as “规则脱敏”，not “绝对安全”。
- Raw export warning is explicit.
- LAN exposure warning is explicit.
- AI/Skill disabled copy does not imply availability.

### 5.3 Accessibility checks

- Buttons have action labels.
- Copy buttons announce success/failure.
- Error panels use `role="alert"` where appropriate.
- Color is not the only indicator for pass/warn/fail.
- Focus is returned after closing dialogs/panels.

## 11. Risks

| Risk | Mitigation |
|---|---|
| Release scope keeps growing | Freeze P0 and move extras to v0.4.1 |
| Tests reveal architectural gaps late | Run backend tests after each previous phase, not only here |
| Docs overpromise safe export | Use precise caveat wording |
| UI gets crowded with new cards | Hide secondary actions behind report sections, keep hierarchy tight |

## 12. Definition of Done

This phase is done when v0.4.0 is documented, tested, self-consistent, and ready for a release candidate without implementing any out-of-scope AI, Skill, desktop, or encryption features.
