## Anti-Patterns Verdict

**AI slop: 大部分通过。不像是 AI 生成的。**

LLM 评估：设计系统经过深思熟虑的策划，而非机械式生成。术语（"行纪"、"翻开目录"、"路线"）展现出以汉语为中心的概念连贯性。没有 uppercase eyebrow、gradient text、glassmorphism、side-stripe borders、hero-metric template、identical card grid。一个细微 tell：登录页居中图标+品牌+标语+输入+CTA 的结构是普遍模式，但纸纹纹理和朱砂品牌拯救了它。

Deterministic scan：`detect.mjs` CLI 返回空数组，exit code 0，零 findings。所有 AI slop 检查规则（purple palette, gradient text, bounce easing, dark glow, oversized h1, hero eyebrow, side-tab border, monotonous spacing）全部通过。

潜在 false positive：`--rice: #f5f0e8` 属于 cream/warm 色系，与 AI 默认配色重叠，但这是刻意的"宣纸/手账"品牌定位，通过 LXGW WenKai 字体、cinnabar 强调色、stitch-line 分隔符进行了充分差异化。

## Overall Impression

一个有清晰设计语言的品牌化界面，token 系统和主题隐喻执行出色。主要弱点不在视觉层面，而在交互完整性：缺少键盘导航、搜索无结果处理不当、桌面端无法取消选择会话。这些问题让一个视觉 8/10 的界面在使用体验上降到 6/10。

## What's Working

1. **主题化 token 系统** — `--ink`/`--rice`/`--cinnabar` 语义命名，100 行 CSS 构建了连贯系统。深浅主题完美对称。
2. **移动/桌面独立布局** — 不是响应式折衷，而是针对不同交互模型的专门优化。底部 tab bar 的 cinnabar dot spring 动画精致。
3. **无障碍基础** — aria-labels 全覆盖，role 属性正确，error focus management，prefers-reduced-motion 媒体查询。

## Priority Issues

### [P1] 搜索无结果显示错误空状态
- **What**: 搜索返回 0 结果时显示通用 EmptyState（"尚无行纪" + ccmemo scan 指令）
- **Why it matters**: 用户已索引了数据，只是搜索不匹配。显示"运行 scan"指令令人困惑，是情感断点。
- **Fix**: 区分"无数据"和"无匹配"状态。无匹配时显示"未找到匹配「{query}」的行纪"，建议放宽搜索。
- **Suggested command**: `/impeccable polish`

### [P1] 桌面端无法取消选择会话
- **What**: 选择会话后无明确机制返回空状态，无关闭按钮、无 Escape 键、点击已选卡片无反应。
- **Why it matters**: 用户被锁定在一个选择中，无法"退出"，违反用户控制原则。
- **Fix**: 添加关闭/返回按钮到 timeline/detail 区域。Escape 键绑定 `setSelectedId(null)`。允许点击已选卡片取消选择。
- **Suggested command**: `/impeccable polish`

### [P2] 无键盘快捷键
- **What**: 开发者工具缺少 Cmd+K 搜索、j/k 导航、Escape 返回等键盘操作。
- **Why it matters**: 目标用户是键盘优先的开发者，无快捷键显著降低效率。
- **Fix**: 添加全局 keyboard handler。Cmd/Ctrl+K 聚焦搜索，侧边栏聚焦时 j/k 或上下箭头导航，Escape 关闭/返回。
- **Suggested command**: `/impeccable polish`

### [P2] Select 组件引用未定义的 --shadow-lg
- **What**: Select.tsx 下拉菜单引用 `var(--shadow-lg)` 但 index.css @theme 中未定义该 token。
- **Why it matters**: 下拉菜单可能无 box-shadow，视觉上扁平，影响浮层层次感。
- **Fix**: 在 index.css @theme 中添加 `--shadow-lg` 或将 Select 引用改为已定义的 `--shadow-elevated`。
- **Suggested command**: `/impeccable polish`

### [P3] 移动端 tab 切换时无会话显示静态空状态
- **What**: 未选择会话时切换到"路线"/"报告"显示空状态文字，感觉像死胡同。
- **Why it matters**: 用户可能认为功能坏了，而非理解需要先选择。
- **Fix**: 空状态中添加可操作按钮"选择一个会话"直接切换到目录 tab。
- **Suggested command**: `/impeccable polish`

## Persona Red Flags

### Alex (Power User — 键盘优先的开发者)
- **无键盘导航** — 无 Cmd+K、j/k、Escape。Alex 不会用鼠标，效率显著下降。
- **无排序控制** — 列表仅按最近排序，无法按项目/时长/错误数排序。
- **无 URL 深度链接** — 选择会话不改变 URL，无法书签或分享。
- **侧边栏不可调大小** — 固定 320px 无法适应长标题。

### Casey (Distracted Mobile User — 手机快速查看)
- **4-5 次交互才能看到内容** — 登录→等待→找到会话→点击→切换 tab。
- **Tab 切换丢失上下文** — 从"路线"切到"目录"再回来，不确定当前查看哪个会话。
- **底部 tab 禁用无解释** — "路线"和"报告"启动时灰色，Casey 可能认为功能坏了。

## Minor Observations

1. Inline style 过度使用（~70% 组件用 `style={{ padding: 'var(--space-4)' }}`），影响 JSX 可读性
2. MobileLayout 缺少 request ID 竞态条件保护（DesktopLayout 有 ref 计数器）
3. `formatRelativeTime` 不随时间更新，保持标签页打开后时间戳过期
4. 深色模式纸纹纹理 0.03 不透明度几乎不可见
5. 登录页 1.1s 错落动画可能在慢设备上延迟表单可用性
6. Select 组件 handleKeyDown 有重复 Enter/Space 处理器（脆弱但巧合地工作）

## Questions to Consider

1. 如果"墨途"是实体笔记本，哪些物理交互最值得数字化？折角=书签？页边注=会话笔记？
2. 210 个会话后怎么办？500、2000、10000 时，当前分页会崩溃。需要日历导航？项目级视图？
3. 底部 tab bar 是唯一的移动导航吗？如果"路线"tab 顶部显示会话标题+状态摘要再滚动到时间线，能否省一次点击？
