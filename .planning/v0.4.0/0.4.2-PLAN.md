# Phase 0.4.2 Plan: 扫描与搜索闭环

**Version:** v0.4.0  
**Phase:** 0.4.2  
**Status:** Planned, not implemented  
**Depends on:** 0.4.1 安全与设置骨架  
**Primary files likely touched during implementation:** scan service, search parser, API handlers, session list/search UI  
**Non-goal for this planning step:** Do not implement code while writing this plan.

## 1. Goal

让用户可以在 Web UI 中完成首次扫描、重新扫描、查看扫描结果，并使用结构化搜索语法快速找到历史会话。

本阶段把 CCMemo 从“需要 CLI 预先准备数据”推进为“Web 可自启动使用”。

## 2. User Stories

1. **作为新用户**，我希望打开 Web 后直接点击“扫描会话目录”，以便不需要回到终端执行 `ccmemo scan`。
2. **作为已有用户**，我希望看到上次扫描时间和重新扫描入口，以便知道数据是否最新。
3. **作为键盘优先用户**，我希望 `project:`、`branch:`、`status:`、`has:errors` 搜索语法真实可用，以便快速缩小范围。

## 3. Scope

### In scope

- Web scan API。
- Scan status 查询。
- 单 scan job 并发保护。
- First-run empty state。
- ScanStatusBar。
- Demo import Web API，可复用现有 demo service。
- Search parser。
- `project:`、`branch:`、`status:`、`has:errors` 后端支持。
- Search syntax help UI。
- 搜索无数据、无结果、错误状态区分。

### Out of scope

- Scan cancellation, unless implementation成本极低。
- 真 SSE，polling 可接受。
- `after:` / `before:` 日期搜索。
- Resume/export。
- 自定义搜索保存。

## 4. Locked Decisions

1. Web scan 与 CLI scan 必须共用 service。
2. 同一时间只允许一个 scan job。
3. 扫描失败不能清空已有索引。
4. Search parser 后端权威，前端只负责提示。
5. `has:errors` 只表示 `error_count > 0`。

## 5. Backend Design

### 5.1 Scan service

Introduce a scan orchestration service around existing project discovery and session indexer.

Conceptual API:

```rust
struct ScanService {
    state: Arc<ScanState>,
}

impl ScanService {
    fn start_scan(&self, mode: ScanMode) -> Result<ScanJobSnapshot>;
    fn get_status(&self) -> ScanStatus;
}
```

### 5.2 Scan status

```ts
interface ScanStatus {
  state: 'idle' | 'running' | 'completed' | 'failed' | 'cancelled'
  mode: 'incremental' | 'full' | null
  started_at: string | null
  finished_at: string | null
  projects_found: number
  files_scanned: number
  sessions_indexed: number
  sessions_updated: number
  events_indexed: number
  errors: ScanError[]
}
```

### 5.3 API endpoints

```text
POST /api/scan
GET  /api/scan/status
POST /api/demo
```

`POST /api/scan` body:

```ts
interface ScanRequest {
  mode: 'incremental' | 'full'
}
```

If scan is already running, return current job snapshot with an “already_running” indicator instead of starting another job.

### 5.4 Search parser

Supported syntax:

```text
project:<value>
branch:<value>
status:<active|completed|interrupted|unrecoverable>
has:errors
```

Parser rules:

- Tokens not matching known filter syntax become free-text search.
- Unknown filter keys remain free text or produce a non-blocking warning, not a 500.
- All DB values must be passed as query parameters.
- `project:` should match project name/path or project ID, exact behavior must be documented.

Conceptual structure:

```rust
struct ParsedSearch {
    text: String,
    project: Option<String>,
    branch: Option<String>,
    status: Option<SessionStatus>,
    has_errors: bool,
    warnings: Vec<String>,
}
```

## 6. Frontend Design

### 6.1 FirstRunEmptyState

Show when session count is zero and not currently loading.

Content:

- Title: 尚未发现行纪
- Body: 扫描本机 Claude Code 会话，建立可搜索目录。
- Primary action: 扫描会话目录
- Secondary action: 导入示例会话
- Metadata: 当前 Claude 配置目录, from settings if available

### 6.2 ScanStatusBar

Placement: session sidebar header area or app header secondary row.

States:

- idle: 上次扫描时间 + 重新扫描
- running: 当前阶段 + counts
- completed: 本次新增/更新摘要
- failed: 错误数量 + 查看详情 + 重试

### 6.3 SearchSyntaxHelp

Show on focus, below SearchBar or as lightweight popover.

Examples:

```text
project:CCMemo
branch:feat/v0.4.0
status:interrupted
has:errors
```

### 6.4 Empty and error states

- No data: show scan/demo actions.
- No search match: show “未找到匹配「query」的行纪”，offer “清空搜索”。
- Search error: show retry and raw error summary.
- Scan error: show file/path warnings but keep existing list visible.

## 8. Acceptance Criteria

- New user can open Web UI and start a scan without using CLI.
- Re-clicking scan while running does not create a second job.
- Scan failure preserves previous indexed data.
- Scan completion refreshes stats and session list.
- `project:`, `branch:`, `status:`, `has:errors` produce expected filtered results.
- Chinese IME input remains compatible.
- Empty/no-match/error states are visually and semantically distinct.

## 9. Test Plan

### Backend tests

- Start incremental scan when idle.
- Reject or return current status when scan already running.
- Full scan requires explicit mode.
- Demo import route works behind auth.
- Search parser cases:
  - plain text
  - `status:interrupted`
  - `project:CCMemo has:errors`
  - unknown filters
  - special characters and quotes
  - Chinese text

### Frontend tests

- First-run empty state renders scan and demo actions.
- Running scan status updates via polling.
- Scan failed state shows retry.
- Search help appears on focus.
- Search no-match state does not tell user to run scan.

## 10. Risks

| Risk | Mitigation |
|---|---|
| Long scan blocks server | Run scan in background task, keep UI polling lightweight |
| Search syntax surprises users | Show help examples and active filter chips |
| Project matching ambiguity | Document matching behavior and prefer project name/path over opaque ID |
| Polling feels stale | Poll faster while running, slower when idle; SSE can follow later |

## 11. Definition of Done

This phase is done when a user can populate CCMemo from the Web UI and reliably use structured search filters to find sessions.
